# Рейсы и счета

Небольшая система учёта рейсов сборных грузов и счетов клиентам.

## Запуск

Нужен PHP 8.2+ с расширением `pdo_sqlite`.

```bash
php bin/reset-db.php
php -S localhost:8000 -t public
```

Открыть http://localhost:8000.

То же через Docker:

```bash
docker run --rm -it -p 8000:8000 -v "$PWD":/app -w /app php:8.4-cli \
    sh -c "php bin/reset-db.php && php -S 0.0.0.0:8000 -t public"
```

`php bin/reset-db.php` пересоздаёт базу `data/app.sqlite` из `data/schema.sql` и `data/seed.sql`. Так можно вернуть
исходные данные в любой момент.

| `lib/` | Подключение к базе, общие функции, расчёт счетов |

| `bin/` | Служебные скрипты |

## Страницы

| Страница | Адрес | Для чего |
|---|---|---|
| Рейсы | `index.php` | Журнал рейсов: куда, когда, на какой машине, сколько стоит |
| Карточка рейса | `trip.php?id=` | Грузы клиентов в рейсе и доля каждого клиента в стоимости |
| Счета клиентов | `invoices.php` | Счета за месяц: сумма, статус, когда отправлен клиенту и выгружен в 1С. Здесь же счета формируют |
| Счёт | `invoice.php?id=` | Из каких рейсов сложилась сумма счёта |
| Загрузка машин | `load_report.php` | Отчёт для логистов: насколько загружена машина по весу и какую часть веса занимает каждый клиент |
| Выгрузка счетов в 1С | `export_1c.php` | Файл для бухгалтерии: отправленные счета, которые ещё не выгружены |



## Что реализовано

1. Распределение стоимости рейса

Изменён алгоритм распределения стоимости рейса между клиентами.
Теперь стоимость распределяется пропорционально объёму грузов (м³), а не их весу.

Особенности реализации:
Грузы группируются по клиентам.
Рассчитываются общий объём и доля каждого клиента.
Значения NULL в поле volume_m3 учитываются как 0.
Денежные суммы рассчитываются в копейках.

Остаток после округления распределяется по методу наибольших дробных остатков.
При одинаковых остатках используется ID клиента для обеспечения детерминированного результата.

Сумма долей клиентов всегда совпадает со стоимостью рейса до копейки.

2. API распределения стоимости

Реализован метод:

GET /api/trip_split.php?trip_id=11

Возвращает JSON с информацией о рейсе и распределением стоимости между клиентами.

В ответ входят:

ID и номер рейса;
стоимость рейса;
ID и название клиента;
количество грузов;
общий вес;
общий объём;
доля клиента;
сумма к оплате.

Коды ответов:

200 — успешный расчёт;
400 — некорректный параметр trip_id;
404 — рейс не найден;
422 — невозможно выполнить распределение.

3. Распределение стоимости в карточке рейса

Данные для отображения получаются через API распределения стоимости.
В таблице отображаются клиенты, количество грузов, вес, объём, доля в процентах и сумма.
Предусмотрена итоговая строка с общей суммой распределения и стоимостью рейса.

4. Предпросмотр и применение счетов

Предпросмотр:
GET /api/billing_preview.php?period=2026-10
Метод рассчитывает изменения счетов за выбранный месяц без изменения данных в базе.
Применение:
POST /api/billing_apply.php
Параметр: period=2026-10
Метод создаёт недостающие счета и пересчитывает существующие по новому правилу.
Повторное применение одного и того же периода не должно создавать дубли или изменять уже рассчитанные суммы.

5. Экран счетов за месяц

Реализована отдельная страница billing.php.
Возможности:
Выбор расчётного месяца.
Предпросмотр изменений.
Сравнение старых и новых сумм по клиентам.
Отображение разницы и итоговых сумм.
Подтверждение применения изменений.
Отображение результата применения.
Результат пересчёта за октябрь 2026
Пересчёт выполнен через новый экран счетов за месяц.
